# Phase 1 所有者概念测试

## 目的

确认当前概念是否准确表达 zisisnotzis 想制作和游玩的游戏。此测试不证明市场需求。

## 阅读材料

只阅读以下内容后作答：

1. `docs/phase-1-concept.md` 的“一页产品提案”。
2. “设计支柱与优先级”。
3. “范围梯度”。

## 问题

请为每题填写简短答案：

1. 不看文档，用一句话描述玩家每场事件主要在做什么。
2. 五个设计支柱中，哪两个最重要？
3. 你更期待哪种高潮：公开压服、紧张撤离、短促冲突，还是其他？
4. 你能否接受准备充分时完全不战斗？
5. 你能否接受不存在完美结果、部分误解无法消除？
6. 你希望失败后立即重试事件，还是让坏结果继续进入后续章节？
7. 你最不希望它变成哪类游戏？
8. 你愿意为一次主要事件观察和准备多久：3–5、5–10、10–20 分钟？
9. 第一版数字原型即使只有文字、平面图和状态变化，你是否愿意试玩？
10. 当前概念中有什么你认为必需但尚未写入的内容？

## 通过判定

- 所有者描述包含“观察 / 准备 / 操纵条件”中的至少两项。
- 最重要支柱与“准备改变结果”不冲突。
- 接受以非战斗解决为有效高潮。
- 接受 Phase 2 使用低保真原型验证规则。

若不通过，优先修改核心概念，不进入引擎制作。
