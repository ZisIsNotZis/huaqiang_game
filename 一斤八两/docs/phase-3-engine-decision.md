# Phase 3 引擎决定

## 决定

首个交互灰盒使用 **HTML5 Canvas + 原生 JavaScript + Node.js 测试运行器**。

这不是最终商业引擎承诺，而是当前环境中最快验证交互、空间阅读和逐步状态模型的原型载体。

## 选择依据

| 要求 | 结果 |
|---|---|
| 当前环境可运行 | Python 与 Node.js 已安装；Godot、Unity、Unreal、Blender 未安装 |
| 自动化测试 | 规则层可直接使用 `node --test` |
| AI 可编辑性 | 文本格式、无二进制场景、结构简单 |
| 可视化 | Canvas 足以表达摊位、人物、通道和撤离方向 |
| 自动试玩与截图 | 可由本地浏览器工具点击、读取和截图 |
| 构建成本 | 无第三方运行依赖，只需静态文件服务器 |
| 后续迁移 | 规则和状态机独立于 Canvas 渲染，可移植到 Godot 或其他三维引擎 |

## 不选择现阶段安装大型引擎的原因

- 当前最危险的未知项仍是玩法因果，而非三维渲染能力。
- 先安装和搭建大型引擎会把时间消耗在编辑器、资产和导出配置上。
- Canvas 原型可以证明逐步状态、按钮交互、空间可读性和结果反馈。

## 重新评估条件

Phase 4 垂直切片前重新评估最终引擎。若需要第三人称角色移动、导航网格、动画状态机和三维灯光，优先评估 Godot 4，其次依据实际团队和资产需求评估 Unreal。
