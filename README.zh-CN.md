# 华强游戏实验室

[English](README.md) · [简体中文](README.zh-CN.md)

**《一斤八两》是一款关于“在冲突开始前就赢下冲突”的第三人称社会潜行原型。** 故事发生在虚构的 1990 年代末中国工业城市铁衡市：观察现场、挪动物件、试探人物，再让证人讲出你需要的那个版本。

> **观察。准备。后果。** 这是一个小型游戏设计实验室，验证观察、社会施压、空间准备和撤离计划能否撑起一场紧张冲突，而不依赖传统战斗循环。

> **状态：无限期暂停（2026-09-29）。** 当前是探索性的 Phase 4 工程候选版，不是完成品，也不是正在推进的制作项目。

![Godot 垂直切片：灰盒街市中的玩家、摊位、证人与互动界面](一斤八两/vertical_slice/screenshots/vertical_slice.png)

*Godot 4.7.1 垂直切片的当前灰盒状态。*

## 快速开始

浏览器灰盒需要 Node.js 和 Python 3，规则原型只需要 Python 3；两者都不用构建。

```bash
# 浏览器灰盒：互动、状态变化和事件日志
cd 一斤八两/greybox
npm test
npm start
# 打开 http://localhost:4173
```

```bash
# Python 规则原型：事实、证人、空间、冲突、叙事
cd 一斤八两/prototype
python -m unittest discover -s tests -v
python play.py
```

运行 3D 切片需要安装 **Godot 4.7.1 stable**，然后：

```bash
export GODOT_BIN=/path/to/Godot_v4.7.1-stable_linux.x86_64
cd 一斤八两/vertical_slice
bash tools/run_godot.sh
bash tools/test_godot.sh
```

`WASD` / 方向键移动，鼠标旋转镜头，`E` 执行最近的有效互动，`Esc` 暂停并释放鼠标。截图和 Linux 导出脚本见 [Godot 垂直切片说明](一斤八两/vertical_slice/README.md)。

## 目前能玩到什么

- **第一章有三条完整路线：** 公开施压、准备后撤离、无准备负伤逃离。每条路线都会给出街坊版与警方版结局，并留下下一章钩子。
- **事实与故事分开记录：** 系统分别追踪实际发生了什么、证人知道什么，以及街坊和警方相信什么。
- **感知规则可以解释：** 距离、视角、物理遮挡和声音决定一个行动是否被看见或听见，界面会说明原因。
- **空间也是资源：** 挪动木凳、选择站位或安排退路，都会改变可用的结果。
- **切片本身是可运行的整体：** 第三人称移动、碰撞、上下文行动、检查点、设置与无障碍选项、程序化音频、自动测试和渲染截图都已接上。
- **三层验证：** Python 规则模型、浏览器灰盒和 Godot 3D 切片逐层暴露假设，避免在昂贵制作之后才发现问题。

## 结构

仓库按验证层级组织：每一层先解决不同的风险，再进入成本更高的下一层。

| 层级 | 路径 | 验证什么 |
| --- | --- | --- |
| 规则原型 | `一斤八两/prototype/` | 事实、证人、空间准备、冲突结果，以及事件的两个公共版本。 |
| 浏览器灰盒 | `一斤八两/greybox/` | 无构建步骤的逐步互动和可读的 NPC 反应。 |
| Godot 切片 | `一斤八两/vertical_slice/` | 第三人称移动、感知、声音、冲突、检查点、设置和渲染证据。 |
| 设计记录 | `一斤八两/docs/` | 阶段门、决策、风险、原创化 / 知识产权边界，以及拆分后的开发计划。 |
| 创意集 | `ideas/` | 同一街市题材下的四个相邻方案。 |
| 流程参考 | `game_dev_flow.md` | 项目采用的阶段化游戏开发流程参考。 |

主设计正文索引在 [`一斤八两/docs/designs/`](一斤八两/docs/designs/)，当前阶段门和证据在 [`一斤八两/docs/`](一斤八两/docs/)。

## 如何开发

- **规则原型：** `cd 一斤八两/prototype && python -m unittest discover -s tests -v`
- **浏览器灰盒：** `cd 一斤八两/greybox && npm test`
- **Godot 切片：** 先设置 `GODOT_BIN`，再执行 `cd 一斤八两/vertical_slice && bash tools/test_godot.sh`
- **文档检查：** `bash 一斤八两/tools/validate_phase0.sh` 和 `bash 一斤八两/tools/validate_phase1.sh`
- **提交前：** 不要让生成状态、本地缓存、导出产物或密钥进入仓库；`.gitignore` 已覆盖主要情况。

灰盒是纯 HTML、CSS 和 ES 模块；原型是纯 Python；切片是带运行、测试、截图和导出脚本的 Godot 项目。

## 如何贡献

先读 [`CONTRIBUTING.md`](CONTRIBUTING.md)，改主项目之前再读[游戏专属协作规范](一斤八两/CONTRIBUTING.md)。保持改动小而有证据，遵守现有阶段门，不要加入未授权媒体或受保护原作的实质性衍生内容。

欢迎可复现的测试、文档修复、无障碍改进、小型规则实验和标注清楚的设计证据。提交 PR 时请说明改动影响哪个阶段门，并附上最小相关测试或截图；文档改动请说明检查了什么。
